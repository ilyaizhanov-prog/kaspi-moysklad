# Бесплатный хостинг для kaspi_feed.xml и фото через GitHub Pages

Это даёт постоянную публичную ссылку для прайс-листа Kaspi и фото товаров,
без своего сервера и без оплаты. Обновление файлов происходит само, по
расписанию, через GitHub Actions.

Заодно тот же репозиторий запускает приём заказов Kaspi → МойСклад
(`sync-orders.yml`) — отдельный, не связанный с хостингом workflow, ему просто
удобно лежать в том же месте.

## Что получится в итоге

- `https://<ваш-логин>.github.io/<репозиторий>/kaspi_feed.xml` — прайс-лист,
  обновляется каждые 20 минут;
- `https://<ваш-логин>.github.io/<репозиторий>/kaspi_images/<артикул>.jpg` —
  фото товаров;
- заказы Kaspi сами попадают в МойСклад каждые 10 минут.

## Шаг 1. Создайте репозиторий на GitHub

1. Зарегистрируйтесь на github.com, если ещё нет аккаунта (бесплатно).
2. Создайте новый репозиторий (кнопка "New repository"). Можно публичный —
   секретов (токенов, паролей) в самом репозитории не будет, они хранятся
   отдельно (см. шаг 3). Название, например, `kaspi-moysklad-sync`.

## Шаг 2. Загрузите туда файлы этого проекта

Из этой папки (`kaspi-github-repo`) нужно загрузить ВСЁ, кроме файлов,
которые и так исключены в `.gitignore` (`config.py` туда не попадёт - и не
должен, в нём были бы секреты, если бы вы его создали локально).

Самый простой способ — через сайт GitHub (без установки git):

1. Откройте свой репозиторий на github.com.
2. "Add file" → "Upload files".
3. Перетащите туда содержимое папки `kaspi-github-repo` (включая скрытую
   папку `.github` — если сайт её не подхватывает при перетаскивании,
   загрузите файлы `.github/workflows/publish-feed.yml` и
   `.github/workflows/sync-orders.yml` через "Add file" → "Create new file",
   указав путь `\.github/workflows/publish-feed.yml` прямо в названии файла -
   GitHub сам создаст вложенные папки).
4. Сделайте commit ("Commit changes").

Если умеете пользоваться git — то же самое привычной командой:

```
git init
git add .
git commit -m "Kaspi <-> MoySklad sync"
git branch -M main
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

## Шаг 3. Добавьте секреты

В репозитории: Settings → Secrets and variables → Actions → New repository
secret. Добавьте по одному (значения — ваши реальные):

Схема — ДВА аккаунта Kaspi: карточки заводятся на аккаунте A (вручную, не через
эти workflow), а остатки/цены и приём заказов идут с аккаунта B (продажи).
Хостинг-workflow используют аккаунт B.

| Имя секрета | Значение | Нужно для |
|---|---|---|
| `MOYSKLAD_LOGIN` | логин пользователя МойСклад для интеграции | фид + заказы |
| `MOYSKLAD_PASSWORD` | его пароль | фид + заказы |
| `STORE_MAP_JSON` | `{"67787641-f0db-11ee-0a80-10a7000edd8f": "PP2"}` (склад Астана → точка PP2) | фид |
| `KASPI_SALES_API_TOKEN` | токен API аккаунта B (продажи) | фид + заказы |
| `KASPI_SALES_MERCHANT_ID` | merchantId аккаунта B (напр. `Ustel`) | фид |
| `KASPI_COMPANY_NAME` | название компании (напр. `Ustel`) | фид |
| `KASPI_IMAGES_BASE_URL` | `https://<ваш-логин>.github.io/<репозиторий>/kaspi_images` | фид (фото) |
| `MOYSKLAD_ORGANIZATION_ID` | ID организации МойСклад (от кого заказы) | только заказы |
| `MOYSKLAD_DEFAULT_STORE_ID` | ID склада для заказов (напр. Астана) | только заказы |
| `MOYSKLAD_AGENT_GROUP_ID` | ID группы контрагентов Kaspi (можно пропустить) | только заказы |

Необязательные (есть значения по умолчанию в коде, секрет можно не создавать):
`KASPI_PRICE_TYPE` (по умолчанию «Цена продажи»), `KASPI_BUNDLE_BRAND`
(по умолчанию `Arto`), `MOYSKLAD_TOKEN`, `MOYSKLAD_DEFAULT_AGENT_ID`.

Секрет `GITHUB_TOKEN` создавать не нужно — GitHub выдаёт его автоматически
каждому workflow.

## Шаг 4. Включите GitHub Pages

1. Settings → Pages.
2. Source: "Deploy from a branch".
3. Branch: `gh-pages` (он появится только ПОСЛЕ первого успешного запуска
   `publish-feed.yml` — см. шаг 5, поэтому к этому шагу можно вернуться чуть
   позже).
4. Сохраните. Через минуту-две GitHub покажет итоговый адрес сайта вида
   `https://<логин>.github.io/<репозиторий>/`.

## Шаг 5. Запустите workflow вручную в первый раз

1. Вкладка "Actions" в репозитории.
2. Слева выберите "Publish Kaspi feed and images".
3. "Run workflow" → "Run workflow" (запуск без ожидания расписания).
4. Подождите, пока появится зелёная галочка. Если красный крестик — откройте
   лог запуска, там будет видно, на каком шаге и с какой ошибкой (чаще всего
   это неверный токен/ID в секретах).
5. После первого успешного запуска появится ветка `gh-pages` - вернитесь к
   шагу 4 и укажите её в настройках Pages, если не сделали раньше.
6. Так же вручную запустите "Sync Kaspi orders to MoySklad", чтобы проверить
   её отдельно.

## Дальше

Дальше всё работает само: `publish-feed.yml` — каждые 20 минут,
`sync-orders.yml` — каждые 10 минут. Ссылку на прайс-лист
(`https://<логин>.github.io/<репозиторий>/kaspi_feed.xml`) укажите в кабинете
Kaspi (Товары → Загрузить прайс-лист → Автоматическая загрузка) — это шаг 5
основной инструкции (`Интеграция_МойСклад_Kaspi.docx`).

Важно: у GitHub Actions расписание иногда срабатывает с задержкой в
несколько минут при высокой нагрузке на сервисы GitHub — это нормально и не
требует исправлений. Также если в репозитории не будет вообще никакой
активности 60 дней, GitHub автоматически отключает запуск по расписанию -
тогда достаточно один раз нажать "Run workflow" вручную, чтобы включить его
снова.
